# 模块文档编写与维护指南

本文件是这套课件的编写规范。可执行流程见 [Skill](../../../../.pi/skills/learning-courseware.md)：接手任务时先读 Skill，需要模板、路由或页面登记的细节时回到本文件。

## 目录与页面职责

```
docs/learning/pi/modules-chain/
  README.md                 总入口：材料地图与阅读顺序
  COURSE.md                 课程地图：学习路径、顺序、时长、自测与练习
  GUIDE.md                  本文件：模板、路由约定、页面登记与维护命令
  build.mjs                 Markdown -> 单文件 index.html，兼链接校验
  index.html                生成物，不手改
  00-full-chain/README.md   全链路
  01-entry-and-config/README.md
  02-agent-loop/README.md
  03-session-and-context/README.md
  04-model-access/README.md
  05-modes-and-tui/README.md
  traces/README.md          贯穿式追踪入口
  GLOSSARY.md               术语表
  DEBUG_MAP.md              排障地图
```

每个模块一个目录，目录内以 `README.md` 为主文档。模块变大时可以在同目录拆出 `routes.md`、`examples.md`，但入口始终是 `README.md`。`traces/` 可以按追踪主题拆成多个文件，入口始终是 `traces/README.md`。

| 页面 | 职责 | 不写什么 |
| --- | --- | --- |
| `README.md` | 材料地图、阅读顺序、Markdown 与网页两个入口、生成命令 | 模块内部函数拆解 |
| `COURSE.md` | 课程地图：先学什么、学习路径、每讲目标与时长、自测和练习安排 | 与模块页重复的源码细节 |
| `00-full-chain/README.md` | 一条真实 query 从 CLI 到回答的时间线，按 S1-S13 编号，跨模块链接 | 单个模块的全部分支和边界情况 |
| `01`-`05` 模块页 | 模块深潜：概念、示例、函数拆解、数据变化、设计取舍、自测与练习 | 其他模块的完整职责 |
| `traces/README.md` | 按生命周期组织的贯穿追踪：消息、工具调用、上下文、事件各自从生到死 | 按文件顺序复述模块内容 |
| `GLOSSARY.md` | 一个术语一个项目内定义，列出别名和源码锚点 | 通用编程词典式解释 |
| `DEBUG_MAP.md` | 现象 -> 层 -> 要检查的数据 -> 函数/源码路由 | 没有定位步骤的故障清单 |
| `GUIDE.md` | 本文件：模板、路由规范、页面登记、并行规则、同步流程 | 具体模块的业务解释 |
| `index.html` | 生成物，供连续阅读、搜索和跳回 IDE | 手写内容 |

页面文件尚未创建时，入口链接会让 `--check` 报“文件不存在”。由页面负责人补齐真实内容并登记；不能在入口保留悬空链接，也不能用空文件占位。页面登记见下文“页面登记”。

## 课件模板

每篇模块文档按教学顺序组织，不按源码文件顺序。标准骨架：

```markdown
# M0X 模块名

## 学完能回答
## 一句话职责
## 大白话总览
## 关键概念
## 运行示例
## 在链路中的位置
### 上游
### 下游
## 文件路由
## 函数路由
## 函数拆解
## 数据变化
## 设计取舍
## 自测
## 练习
## 常见误解
## 继续阅读
```

各部分写什么，以及最常见的失败写法：

| 部分 | 写什么 | 常见失败写法 |
| --- | --- | --- |
| 学完能回答 | 5 到 8 个可用源码证据回答的问题，覆盖成功路径、失败分支和设计原因 | “了解 XX”“熟悉 XX”这类无法验证的目标 |
| 一句话职责 | 只写一个职责，并说明它明确不负责什么 | 把整条链路写进一句话，说明模块该拆 |
| 大白话总览 | 用类比或一条具体 trace 建立直觉，指出容易反过来的地方 | 堆术语、复述目录，没有具体输入和输出 |
| 关键概念 | 容易混淆的词，给出项目内含义、区别和一个例子 | 抄通用定义，不说明在本仓库指什么 |
| 运行示例 | 真实输入，以及模块内部实际产生的对象、字段、消息或事件 | 编造字段名、用 `foo`/`bar` 占位、只写伪代码 |
| 在链路中的位置 | 上游谁调用、下游调用谁、对应全链路哪一步，并给链接 | 只写“被 X 调用”，不写数据如何进出 |
| 文件路由 / 函数路由 | 按机制分组；稳定 ID、符号、位置、作用 | 按文件字母序堆表，或只给表不解释 |
| 函数拆解 | 每个关键函数的职责、输入、输出、副作用、编号步骤、子函数、数据变化、失败分支、设计原因 | 逐行翻译源码，不写数据变化，不写失败路径，不写为什么 |
| 数据变化 | 同一份数据在进入、处理、离开模块时的样子，用表格或短 trace | 只列类型定义，没有具体实例的前后对比 |
| 设计取舍 | 为什么这样分层，换一种写法会坏在哪，代价是什么 | 只夸当前设计，不给替代方案和代价 |
| 自测 | 能用自己话回答的问题，附答案或源码定位 | “想一想”式开放问题，没有可核对答案 |
| 练习 | 改一个参数、加一条日志、画一张数据流图等小任务，能观察结果 | 要求实现完整功能，或依赖真实 API key、网络和付费调用 |
| 常见误解 | 误解、纠正、源码证据三件事，例如“模型返回 toolCall 时工具已经执行了吗” | 树稻草人，或重复正文已经说清的内容 |
| 继续阅读 | 前后模块、全链路步骤、相关 trace | 把所有页面链接堆在末尾 |

质量底线：

- 每个模块必须同时有“学完能回答 / 大白话总览 / 具体运行示例 / 函数内部拆解 / 自测 / 练习 / 常见误解”。不能只写路由表。按机制命名的走读章节（例如“打印模式”“交互模式”“RPC 模式”）只要包含函数内部步骤，算作函数拆解。
- 示例必须来自真实代码。字段名、事件名、默认值、错误文字都要能在源码或类型声明中找到。
- 区分三件事：TypeScript 编译期类型检查、运行时 schema/参数校验、测试实际证明的范围。不能因为类型允许就声称某个分支已被测试。
- 失败、取消、截断、重试等路径要单独说明，不能只写成功路径。
- 函数拆解要落到子函数和数据结构：谁调谁、哪些字段被替换、哪些数组被 push、哪一步可能抛错。
- 中文直接、简洁，不用 emoji，不用“感谢阅读”等填充语。

## 路由 ID

格式：`M<模块两位>.<机制>.<动作>`，例如：

- `M02.loop.run`：Agent 循环的主循环。
- `M03.store.projection`：请求前从会话条目投影模型上下文。
- `M04.runtime.simple`：ModelRuntime 的通用流入口。

规则：

- ID 一经使用不重命名；函数改名时保留 ID，只更新符号和链接。
- 一个 ID 只指向一个符号。重载函数选最有代表性的入口行。
- 路由表按机制分组，不按文件字母序堆在一起。
- 表格里的位置链接格式固定：`[file.ts:668](../../../../../packages/.../file.ts#L668 "可搜索的符号文本")`。
- 链接标题（`"..."`）不是给人看的说明，而是校验脚本的搜索锚点。它必须在目标文件里以字面量出现，且尽量唯一。裸函数名容易匹配多处，优先写 `async prompt(`、`function runLoop(` 这类更长字面量。
- 文件级路由不带 `#L`，例如 `[agent-loop.ts](../../../../../packages/agent/src/agent-loop.ts "agent-loop")` 只用于“这个文件整体”。

### 行号漂移

`build.mjs --check` 会：

1. 检查链接文件是否存在。
2. 检查 `#L行号` 是否落在文件行数内。
3. 如果有标题锚点，在当前行号附近和全文搜索该字面量；找不到报错，匹配过多报歧义警告。

`build.mjs --fix` 会取最近的匹配行，同时改写链接文本里的 `:行号` 和 URL 里的 `#L行号`。修完再跑一次 `--check`，并检查 Markdown diff。歧义警告不能默认忽略：`--fix` 可能选中同名重载的错误位置，应先把标题锚点改得更具体。不要手工批量加减行号。

## 页面登记

网页生成器只读取 `build.mjs` 顶部的 `PAGES` 数组。数组项形如：

```js
{ id: "02-agent-loop", file: "02-agent-loop/README.md", title: "02 Agent 循环", short: "02", group: "模块" }
```

字段含义：

- `id`：网页路由身份，对应 `#/<id>@<anchor>`。小写、稳定，不要随意改。
- `file`：相对 `modules-chain/` 的 Markdown 路径。
- `title`：导航和页面标题。
- `short`：顶部导航芯片文字。
- `group`：导航分组，例如“开始”“主线”“模块”“速查”“维护”。

新增页面时：

1. 先写出有真实内容的 Markdown 页面。
2. 在 `PAGES` 中加一项。
3. 同步 `README.md` 的材料地图和阅读顺序。
4. 同步 `COURSE.md` 的学习路径。
5. 在相邻页面的“继续阅读”中加链接。
6. 跑 `--check`、重新生成 `index.html`，在网页里点一次页面按钮。

未登记的页面不会出现在网页导航中，也不会被链接校验；`#/<id>` 会落到首页。生成物 `index.html` 不手改，页面内容和导航都从 Markdown 与 `PAGES` 重建。

## 并行代理与文件所有权

- 一个代理只拥有一组不相交的文件。其他代理的页面可以读，不能改；发现别人的链接坏了，报告给对应负责人或最终汇总者，不要顺手修。
- 不 stage、不 commit 别人的文件。只 `git add <自己的路径>`，禁止 `git add -A`、`git add .`。
- `build.mjs`、`README.md`、`COURSE.md` 以及学习分支的 `STUDY_PROGRESS.md`、`STUDY_LOG.md` 是共享文件，必须指定单一负责人，或在页面写完后由汇总者统一登记和记录。
- 源码写入者未停止时，不跑全仓格式化或 `npm run check`。先冻结写入者，再跑仓库级检查。
- 并行工作合并后，由汇总者统一跑 `--check`、重新生成 `index.html`、核对暂存路径和工作区状态。
- 未完成的草稿不进入阶段提交。中文行数多不代表完成；完成的标准是章节齐全、源码读全、链接通过、示例可核对。
- 学习分支的提交和推送遵循 `AGENTS.md`：只收录已验证的完成工作，保留正常 Git 钩子，不强制推送。

## 上游更新后的同步流程

1. 先确认工作区状态和当前分支。不要为了同步切换分支、创建 worktree、stash 或 reset。
2. 用 `git log --oneline <上次审阅的 commit>..origin/main -- <相关路径>` 和 `git diff <上次审阅的 commit>..origin/main -- <相关路径>` 看清实际变化，不能只看文件数量。
3. 完整阅读变更的源码及相关调用方、被调方，核对类型和运行时校验。
4. 对照 `docs/learning/pi/STUDY_PROGRESS.md` 和覆盖清单，列出受影响的页面、路由、示例和锚点。
5. 更新解释、示例、行号和锚点。代码行为变化时，相关结论要重写，不能只改行号。
6. 跑 `--check`；有真实行号漂移再跑 `--fix`；重新生成 `index.html`；在网页里验证页面按钮和跨页锚点。
7. 行为变化涉及源码时，按包根目录跑相关测试；非 e2e 的全量测试用 `./test.sh`。不要运行 `npm test`，除非用户明确要求。
8. 在 `docs/learning/pi/STUDY_LOG.md` 记录实际审阅的上游 commit、更新范围和验证结果。脚本通过只证明链接和行号有效，不是语义审阅；不能把自动 stale 检查当成人工复核。
9. 阶段工作完成后更新 `STUDY_PROGRESS.md` 和覆盖清单。生成物、第三方代码和只有部分注释的文件不能计为完成。

rebase 时只解决自己修改过的文件冲突。冲突出现在未修改的文件里，停止并询问用户。永远不要 force push。

## 全链路文档的写法

- 按时间顺序编号步骤，每一步都给出入口函数链接。
- 每一步只回答三个问题：谁调用、做了什么、产出什么对象/事件。
- 工具往返单独放大，因为它是“一次 prompt 变成多次模型请求”的关键。
- 交互模式与打印模式分开写差异，不重复共同链路。
- 多轮单独一节，讲清楚“哪些状态跨轮保留、哪些每轮重建”。

## 跨模块链接

同一套文档内部用相对路径链接到模块入口或锚点：

```markdown
[会话投影](../03-session-and-context/README.md#m03-store-projection)
```

锚点用显式 HTML，避免中文标题自动 slug 在不同渲染器里不一致：

```markdown
<a id="m03-store-projection"></a>
### 请求前投影：buildSessionProjection
```

同页锚点也要显式 `id`；`--check` 找不到时会告警。网页生成器会把已登记页面的 `.md#anchor` 转成 `#/page@anchor`，Markdown 版本保持原样。目标页面未登记时，链接不会转换，锚点也不会被校验。

## 网页生成器

`build.mjs` 不依赖第三方包：

- 只读取 `PAGES` 中登记的页面。当前已登记 `README.md`、`COURSE.md`、全链路、`traces/`、五个模块、`GLOSSARY.md`、`DEBUG_MAP.md` 和 `GUIDE.md`。新增页面必须先登记才会进入网页和链接校验；`traces/` 拆成多页时，每个文件单独登记。
- 用内置的小型 Markdown 渲染器生成 HTML；支持标题、段落、列表（含列表内缩进代码块）、表格、代码块、引用、行内代码、粗体、链接、显式锚点。
- 把源码链接转成可点击的路由芯片；`href` 仍是 IDE 的 URL scheme（默认 `webstorm://`，`--ide=vscode` / `--ide=pycharm` 切换），以构建时的仓库绝对路径生成，换机器后重新构建即可。
- 生成单文件 `index.html`，内联 CSS/JS 和全部页面内容，不产生 `assets/`。
- `--serve` 启动本地打开服务：监听 `127.0.0.1:4917`（`--port=` 可改），提供 `/ping`、`/open` 和页面本身。`/open` 只接受 GET、只接受来自本文档页（`file://` 的 `Origin: null`）或同端口 `127.0.0.1`/`localhost` 页面的请求，并拒绝跨站 `Sec-Fetch-Site`；文件必须存在且在仓库内，解析为绝对路径后执行系统级 `open "<ide>://..."`。这项检查挡普通网页的跨站请求，但本地服务不是安全边界：本机进程、以及能构造 `Origin: null` 的沙箱页面仍可调用 `/open`。
- 页面上的普通点击不直接跟随 `href`，而是请求本地服务。原因：JCEF（IDE 内置 Preview）不支持自定义协议，直接跳转会显示 `ERR_UNKNOWN_URL_SCHEME` 并替换页面。服务未启动时，点击退化为复制 `path:line` 并提示，页面不受影响。
- Alt+点击芯片复制 `path:line`，Shift+点击复制 `path`。

## 常见故障

- **`--check` 报文件不存在**：入口链接指向的页面还没创建，或路径写错。由页面负责人补齐真实内容并登记；不要在入口留悬空链接，也不要用空文件占位。
- **网页里没有新页面**：没有在 `PAGES` 登记。登记后重新生成 `index.html`。
- **`ERR_UNKNOWN_URL_SCHEME`**：在 JCEF 预览里直接打开了 `webstorm://` 这类自定义协议。用 `--serve` 启动本地打开服务，从页面点击路由芯片；不要手工把芯片改成裸协议链接。
- **端口冲突**：`--port=4918` 换端口重新生成并启动；页面里的服务地址会随生成结果更新。
- **`--check` 歧义警告**：同一字面量在同一文件出现多次。把链接标题改得更具体，再跑 `--fix` 或核对行号；不要直接忽略。
- **跨页锚点找不到**：缺少显式 `<a id="..."></a>`、拼写不一致，或目标页面未登记。先修锚点，再跑 `--check`。
- **页面按钮或 `#/page@anchor` 不工作**：`PAGES` 的 `id`、链接里的 id、页面锚点三者不一致。修登记后重新生成。
- **手改 `index.html` 后丢失**：生成物会被重建覆盖。改 Markdown 或 `build.mjs`，然后重新生成。
- **行号漂移**：先 `--check`，再 `--fix`，检查 diff 和歧义警告；不要批量手改行号。
- **示例字段不存在**：回到类型声明和真正构造对象的代码核对。只出现在测试夹具里的字段要明确标注，不能写成生产行为。

## 提交前检查

```bash
node docs/learning/pi/modules-chain/build.mjs --check
node docs/learning/pi/modules-chain/build.mjs
git status --short docs/learning/pi/modules-chain
```

逐项确认：

- [ ] 只改了自己拥有的文件；没有改源码或生成物。
- [ ] 目标源码已完整阅读，调用方、被调方、类型和运行时校验已核对。
- [ ] 模块页包含全部必需章节，不是只有路由表。
- [ ] 运行示例来自真实代码，字段名、事件名、默认值和错误文字没有编造。
- [ ] 路由 ID 稳定；链接标题是可搜索的字面量且尽量唯一；跨页锚点有显式 `id`。
- [ ] 新页面已登记到 `PAGES`、`README.md`、`COURSE.md`，相邻页面已加链接。
- [ ] `--check` 对自己负责的页面为 0 error；别人页面的 error 已报告而不是隐藏；每条 warning 都已判断并处理。
- [ ] `index.html` 已重新生成；页面按钮、跨页锚点、搜索和源码芯片已在预览中验证。
- [ ] `git status --short` 和暂存路径只包含自己的改动。
- [ ] 阶段工作需要时，`STUDY_LOG.md` 记录了实际审阅的上游 commit 和检查结果，`STUDY_PROGRESS.md` 已更新。
- [ ] 没有密钥、token、凭据或个人信息。

生成器只写 `index.html`，不会改 Markdown。`--fix` 会改 Markdown 行号，运行后要单独检查 diff。
